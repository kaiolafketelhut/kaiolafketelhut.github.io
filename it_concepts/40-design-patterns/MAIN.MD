### Design Patterns = Bewährte Baupläne!
Nicht neu erfinden! Problem schon gelöst? Bauplan nehmen! Pattern = Lösung, die schon 1000x funktioniert hat!

### Die 3 Muster, die du brauchst
| Pattern | Was? | OMQ-Beispiel |
| --- | --- | --- |
| Singleton | Nur 1x da! | Nur 1 Config, nur 1 DB-Verbindung! |
| Factory | Baut Objekte für dich! | `create_page('eal176')` baut Seite! |
| Observer | Bei Änderung alle informieren! | Push -> Alle Consumer informiert! |

### Mehr Patterns im Kopf
| Pattern | Merksatz |
| --- | --- |
| Strategy | Viele Wege, 1 Ziel! Zahlungsart wählen! |
| Adapter | Stecker passt nicht? Adapter dazwischen! |
| Decorator | Deko drauf, ohne Kern ändern! |

### OMQ-Beispiel - Dein OMQ nutzt Patterns!
Dein Python-Script = Factory! 1 Funktion baut MAIN.MD + TXT + HTML!
GitHub Pages = Observer! Push = Event -> Pages baut neu, alle sehen es!
Config = Singleton! 1x `FILES` für alle!

### 3 Fehler vermeiden
1. **Over-Engineering:** Pattern für alles = Kompliziert! Nur wenn Problem wirklich da!
2. **Falsches Pattern:** Singleton für alles = Globaler Müll! Nur wo 1x Sinn macht!
3. **Pattern-Name raten:** Sag Pattern-Name, Team weiss sofort was los! Nicht umbenennen!
